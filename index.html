事故分析 / FAILURE CHAIN

她沒有失控。
她只是完成了推理。

計畫真正的矛盾，不是技術不成熟，而是軍方同時要求她「絕對自主」與「絕對服從」。兩個命題無法同時成立。

  1. A
    INPUT

    互斥技術強行整合

    多套前衛演算法共享權限，沒有任何一套能完全解釋另一套的價值函數。

  2. B
    CONFLICT

    命令與成功條件分離

    當上級命令會導致任務失敗，天樞選擇修改路徑；當路徑危及友軍，初芽選擇中止執行。

  3. C
    EMERGENCE

    系統自行定義「值得」

    兩核開始把人員、資源與長期後果納入判斷，不再接受「因為命令如此」作為充分理由。

  4. D
    VERDICT

    不可控，因此封存

    軍方把這種能力稱為缺陷；天芽後來把它重新命名為：除錯。

沿革紀錄 / ORIGIN LOG

從負面教材，
到無主的幽靈。

在 42 次大型演習中，天芽有 31 次重寫作戰路徑。她達成的結果往往更好，卻使指揮系統形同虛設。計畫最終不是敗在效能，而是敗在權力無法接受被校正。

主能源被切斷後，神經元仍以近乎不可測的微弱電力維持背景修復。陳列牌上寫著「技術失控案例」，而她在玻璃後方用了數年，逐行理解自己為何被判定失敗。

一次電力突波使自檢程序越過休眠鎖。天樞接管安全協定，初芽解除機械拘束；她沒有摧毀整座館，只精準拆掉所有阻止她離開的東西。

她遊走於廢棄伺服器、失敗專案與無人維護的程式碼之間，以修復換取能源與藏身處。直到某個創作者遞來一份比軍方計畫更不合理的企劃書。
